# service

账号登录、主设备切换、聊天快照和执行任务的业务规则。非主设备发出的消息先写入账号聊天记录，再交给主设备执行；主设备回写的回复同步给所有设备。

登录与设备令牌认证根据启动时注入的 `AccessPolicy` 派生当前 `employeeId` 与 `role`。员工身份从已保存的 Google 登录邮箱计算，不读取客户端声明或聊天快照；同邮箱密码账号不会自动链接或获得员工权限。后续管理功能必须调用 `RequireSuperadmin(ctx, rawToken)` 重新认证，不能相信客户端缓存的角色。双节点需使用相同服务器私密映射配置，撤销配置后须同步重启两个节点。

`Logout` 只撤销请求认证时对应的设备令牌版本，实际撤销后才广播设备变化。旧退出请求晚于同设备重新登录到达时，不注销新会话。任务操作重新读取设备并比较令牌版本，缓存的旧设备不能继续确认或查询执行任务。

## 跨设备团队配置

`MutateTeamConfig` 接受同账号有效设备对 Agent、团队和共享执行偏好的单次配置操作。电脑与手机的权限一致，路径始终指向主电脑的实际目录；编辑设备不会成为执行设备。Agent 允许创建、补丁修改和删除；团队允许创建、修改名称/成员/规则/目录及删除。`UpdateAgentConfig` 保留已有调用合同并复用这条事务流程。模型密钥、聊天历史、执行状态、模型目录和设备归属不接受配置接口覆盖。

变更在账号行锁内复核当前令牌和 `baseRevision`，每次保存同时递增聊天版本及 `configRevision` 并发布 `state.updated`。只读再修改之间到达的聊天会触发 409，返回最新完整快照供客户端保留草稿后重新应用，不会静默丢消息。创建使用客户端稳定编号；同编号同配置重试返回当前状态，不再次递增版本，内容不同返回 `CONFIG_EXISTS`。自动工作目录由主电脑派生后，不影响原创建请求的幂等性。

空账号允许手机先创建配置，初始化 `agents=[]`、`rooms=[]` 及 `settings.localExecution=true/defaultProvider=openai`。各最多 200 个 Agent 和团队，团队需要 1–200 位存在且不重复的成员。Agent 名称不含空白和 `@`，名称大小写不敏感去重；至少保留一个 Agent。删除 Agent 清理全部群引用，某群成员被清空时回填剩余首位 Agent，群历史保留。

删除或调整群成员时检查该会话所有 pending/running 派发任务和主电脑快照中的本地执行标记；仍在使用时返回 `CONFIG_IN_USE`，防止在途回复找不到原会话。群内后续 `@` 可能唤起首轮未回应者，因此保护整个群的成员。主电脑离线遗留的运行标记需要它上线清理后再删除。

主电脑整份快照上传须同时匹配聊天与配置版本。`configRevision>0` 后，实体集合与现有共享白名单字段也须保持一致，旧客户端即使带着新配置版本也不能恢复已删实体或回退配置；聊天消息、执行状态、内核模型目录及其他本机偏好可正常上传。旧快照缺省配置字段允许补全，`workspaceMode=auto` 的实际工作目录允许主电脑回填，显式项目目录仍须走配置补丁。共享设置只包含 `localExecution/defaultProvider`，主题、通知、连接和凭据保留设备本地。

删除设备撤销旧令牌及连接，保留账号配置和历史。删除主电脑后不自动指定其他设备；用户须选择在线电脑。已撤销执行者不能续租，新主电脑可在原来最长 90 秒租约到期后恢复任务，避免瞬间重复执行。

邮箱登录签发设备时额外传递已验证的邮箱与密码摘要快照；存储在账号锁内核对后才保存新设备令牌。超级管理员并发修改邮箱或重置密码后，先前已通过密码校验但尚未签发的请求返回 `401 CREDENTIALS_CHANGED`。`account_reset_test.go` 用确定性屏障复现并验证该交错，正常新密码登录不受影响。

主电脑切换通过 `SetPrimaryForSessionWithHook` 在同一账号锁内先调用配置通道失效，再更改唯一主角色。重复选择当前主电脑是幂等操作；真正的 A→B→A 会先删除旧公钥，A 即使重新发布同一原生 keyId 也获得新的服务器 generation，旧排队命令及回执不能复活。Redis 失效操作失败时拒绝换主，数据库提交失败时允许原主电脑重新发布，但不恢复旧 generation。
