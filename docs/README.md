# Chorus 界面与文档导航

本目录保存面向使用者的产品截图与辅助说明。项目的安装、开发、构建和部署入口统一放在 [仓库根 README](../README.md)；各模块的实现细节由对应目录 README 维护。

## 团队房间界面

![Chorus 架构评审房主界面](chorus-team-room-overview.png)

这张图展示 Chorus 的核心使用方式：把不同职责的 Agent 放进一个团队，让它们在同一份上下文中讨论，并由主电脑上的真实模型或编程 CLI 执行任务。

### 1. 左侧：团队和 Agent

- “团队空间”列出共享讨论房间。每个团队可以拥有不同成员和协作规则。
- “Agents”列出全局角色。一个 Agent 可以加入多个团队，也可以拥有独立私聊。
- 选择团队时，中间进入团队讨论；选择 Agent 时，中间切换为私聊，右侧显示该 Agent 的配置。
- 左下角是当前登录账号和设置入口。对外交付截图不展示真实个人邮箱、令牌或内部凭据。

### 2. 中间顶部：当前团队成员

成员标签说明谁能看到本团队上下文并参与当前任务。点击成员可以进入私聊；在团队消息中使用 `@成员名`，可以明确指定首个处理者或让成员间继续交接。

自然群聊并不要求每个成员轮流发言。每位成员会结合职责与已完成上下文判断相关性，无关成员保持沉默，避免重复回答。需要严格控制时，可在右侧把协作方式改为“仅 `@` 回应”。

### 3. 中间主体：讨论与执行结果

主体区域展示用户消息、Agent 回复、流式正文和执行状态。团队成员共享已经完成的上下文；同一轮独立成员可以并行，涉及同一工作区写入的任务会排队，减少文件冲突。

首次打开时的引导卡会提示尚未完成的模型、密钥或主电脑配置。系统不会在后台不可用时伪造回答，也不会静默切换到另一个模型。

### 4. 右侧：团队或 Agent 设置

选择团队时，右侧可以：

- 修改团队名称；
- 在自然群聊和仅 `@` 回应之间切换；
- 查看、配置、移出或加入成员；
- 了解团队共享内容和执行方式。

选择单个 Agent 时，右侧改为 Agent 信息，包括角色说明、后台、模型、执行内核和工作区。项目路径始终是主电脑上的路径，即使配置操作来自手机或另一台电脑。

### 5. 底部：输入任务和附件

输入框用于描述目标，也可以 `@` 指定成员并添加文本附件。发送后，中转站保存消息和任务，主电脑领取并执行，再把流式进度和最终结果同步回来。

每次最多导入 5 个文本附件，单文件 256 KB、合计 512 KB。代码仓库不会因为发送消息而自动上传；只有被主电脑上相应模型或 CLI 主动读取的工作区文件会参与任务。

### 6. Android 布局

Android 与 Mac 使用 `shared/web/` 中的同一套工作台：

- 左侧团队/Agent 列表收进菜单抽屉；
- 右侧详情以浮层打开；
- 团队、私聊、草稿、配置和进度通过同一中转站同步；
- 手机只负责交互与管理，不在本机运行 Codex、Claude Code 或 Cursor。

主电脑离线时，手机发送的任务会保留在中转站；主电脑上线并保持主设备资格后继续领取。

## 从界面到执行

```text
输入任务
  └─ 中转站持久化消息和任务
       └─ 通知同账号主电脑领取
            └─ 模型或编程 CLI 在主电脑执行
                 └─ 流式进度与最终结果同步到所有设备
```

模型密钥和 CLI 登录留在主电脑，工作区文件也留在主电脑。中转站保存账号、聊天快照、配置和任务队列，但不作为 Agent 执行环境。

## 截图维护约定

更新产品截图前应先检查：

1. 遮盖个人邮箱、姓名、头像、工号和设备名称等身份信息。
2. 不出现 API Key、Token、OAuth secret、数据库地址或后台管理员配置。
3. 示例团队和任务不包含真实客户数据、内部代码或未公开项目名称。
4. 图片文件使用含义清楚的英文小写名称，并同步更新本页和根 README 的引用。
